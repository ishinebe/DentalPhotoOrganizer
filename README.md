# DentalPhotoOrganizer

Phase 8-B / version 0.9.1

DentalPhotoOrganizer は、SDカードやローカルフォルダに混在した大量の歯科臨床写真を、患者ごとに安全かつ効率的に整理し、人間の確認後に院内の正式保存先へ書き出すための Windows デスクトップアプリです。

本プロジェクトは、汎用的な歯科画像管理システムを作ることを主目的としません。中心課題は、現在人手で行っている「患者ごとの写真振り分け・確認・フォルダ作成・保存」の負担を減らすことです。

## Product focus

最重要の判断基準は次です。

> その機能は、患者ごとの写真整理に必要な人間の作業を、安全性を損なわずに減らすか。

この問いに直接寄与しない機能は、コア機能として扱う前に必要性を再検討します。

### Core responsibilities

- 写真の安全な取り込み
- QR / バーコード、撮影順、時刻などを利用した患者ごとの仮整理
- 別患者写真の混入や患者境界の確認支援
- 人間による最終確認
- 写真の移動・分離・統合などの修正操作
- 確認済み写真の安全な正式書き出し
- 正式保存先を後から見つけるための軽量な検索
- 確認・修正・書き出しの追跡可能性

### Not the primary goal

以下は有用な場合がありますが、患者振り分けを成立させるための必須機能ではありません。

- 高機能な患者写真ライブラリ
- 治療前後の経時比較ビュー
- 写真アノテーション
- 患者説明資料の作成
- 写真種別や左右の完全自動分類
- 5枚法 / 9枚法 / 14枚法の分類精度そのものを製品目的にすること

撮影方法・写真種別・担当医・撮影者などの情報は、臨床上・検索上有用な補助メタデータとして保持できます。ただし、それらの入力や修正が新たな大きな手作業負担にならないようにします。

## Data and export model

原本画像は変更・削除・上書き・移動しません。

アプリ内部では「患者写真セット」を確認・修正の処理単位として扱います。一方、最終保存の基本単位は **患者 × 撮影日** とします。同一患者・同一撮影日の写真は、複数の患者写真セット由来であっても、同じ正式保存先へ整理できる設計を目指します。

最終書き出し後の院内フォルダを、整理済み写真の長期的な正本として扱います。Supabase / DB は、処理状態、患者割り当て、履歴、検索索引などを管理するために使用し、写真そのものをアプリへ囲い込むことを目的としません。

出力ファイル名は、写真種別や左右など変更され得る意味を埋め込まず、`001.jpg`, `002.jpg` のような単純な連番を基本方針とします。

## Target workflow

1. 写真を取り込む。
2. 原本画像を変更せず管理対象として登録する。
3. QR / バーコード、撮影順、時刻、その他の手掛かりで患者ごとに仮整理する。
4. 人間が「同じ患者の写真だけで構成されているか」を確認する。
5. 必要に応じて写真を別患者へ移動、新しい患者へ分離、または統合する。
6. 確認済み写真を患者 × 撮影日の正式保存先へ安全に書き出す。
7. 必要になったとき、患者IDや撮影日から正式保存先を見つけて開く。

AIや自動分類は、この流れを効率化する手段の一つです。最終的な患者割り当ての判断者ではありません。

## Branch

現在の実装本体と開発作業は `master` ブランチです。

GitHub の default branch が `main` を指している場合でも、最新実装は `origin/master` を確認してください。

## Current implementation

現在の実装には、以下が含まれます。

- Electron / React / TypeScript による Windows デスクトップUI
- ローカル画像フォルダからの取り込み
- Supabase への画像メタデータ登録
- `file_hash` による重複スキップ
- QR情報などを利用した患者ごとの仮分類
- 患者情報・写真確認画面
- 写真の別患者への移動、分離、統合
- 人間による確認完了
- 書き出し前確認
- 患者ごとのコピー書き出し
- 正式書き出し先パスの記録
- 患者ID、撮影日、担当医、撮影者等による検索
- 正式保存先フォルダを開く導線
- 撮影方法、写真種別、撮影基準チェックなどの補助機能

既存実装に存在する機能が、すべて今後のコア要件であるとは限りません。新しい設計判断では `docs/vision.md`、`docs/principles.md`、`docs/decisions.md` を優先してください。

## Development

Install dependencies:

```bash
npm install
```

Start development mode:

```bash
npm run dev
```

Type check / lint:

```bash
npm run lint
```

Production build:

```bash
npm run build
```

## Safety notes

- `.env` / `.env.local` や鍵情報をコミットしないでください。
- 実患者写真、書き出し結果、ローカルテスト出力を意図せずGitへ追加しないでください。
- `git add .` を使用する前に、必ず `git status` で追加対象を確認してください。
- 本番運用前には RLS、認証、権限、監査ログなどのセキュリティ設計が必要です。
